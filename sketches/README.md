# 界面方向比较

这是一组一次性设计草案，用于在改动业务代码前比较信息架构、密度和交互姿态。

| 维度 | 清晰目录 | 交易工作台 | 校园双轨看板 |
| --- | --- | --- | --- |
| 主表面 | Explore | Operate | Explore |
| 默认焦点 | 搜索与筛选 | 下一步动作与协议状态 | 资源/技能并列发现 |
| 信息密度 | 中 | 高 | 中 |
| 学习成本 | 低 | 中 | 中 |
| 交易闭环可见性 | 中 | 高 | 中高 |
| 管理端延展性 | 中 | 高 | 中 |
| 风险 | 容易弱化交易任务 | 初见稍显严肃 | 双轨在小屏需折叠 |

## 建议

优先选择“交易工作台”作为整体壳层，并吸收“清晰目录”的广场浏览方式。它最符合操作型校园平台：交易状态、协议快照、双方确认、认证与治理都能用同一套列表 + 检查器结构扩展。

“校园双轨看板”适合保留为广场首页的候选，但不建议把看板式布局延伸到管理端或交易详情。

## 业务硬约束

- 手机号验证码只证明用户控制该手机号，不代表学生身份。
- 学生身份由用户提交带一次性挑战码的学生证或海大 e 卡材料，并由管理员人工审核。
- 发布者接受后仍需发起者确认，协议才正式达成。
- 交付后双方分别确认；只有两个完成确认都存在，交易才完成。
- 平台不托管资金，也不验证线下微信付款真伪。
- 只有已完成交易可以评价；争议中暂停评价与信用结算。

打开 `sketches/index.html` 可查看总览，或直接打开各方案的 `index.html`。
